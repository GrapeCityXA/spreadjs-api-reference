## What this is

Each `v<version>/` directory is a full API reference generated by TypeDoc from the SpreadJS source comments. Prose descriptions are in **Chinese**; signatures, type names and example code are language-neutral.

## Resolving a symbol — do this, not that

**Do not construct file paths from class names.** Filenames usually equal the fully-qualified name, but TypeDoc appends `-1` when two entities collide (23 such files exist, e.g. `v19.1/excelio/classes/GC.Spread.Excel.IO-1.md`). Glob first:

```bash
# Find the file that defines a class (repo-wide, any version)
find . -name "GC.Spread.Sheets.Worksheet.md" -not -path "./.git/*"

# Or search by heading when you only know the short name
grep -rln "^# Class: Worksheet$" v19.1/

# Find every file mentioning a member
grep -rn "getActiveSheet" v19.1/classes/GC.Spread.Sheets.Workbook.md
```

## Where things live

| Symbol kind | Path under `v19.1/` |
| --- | --- |
| Namespace / module | `modules/GC.Spread.Sheets.md` — **entry point, start here** |
| Class | `classes/GC.Spread.Sheets.Worksheet.md` |
| Interface | `interfaces/GC.Spread.Sheets.ISize.md` |
| Enumeration | `enums/GC.Spread.Sheets.HorizontalAlign.md` |
| Designer component | `designer/{modules,classes,interfaces,enums}/` |
| Excel import/export | `excelio/{modules,classes,enums}/` — **no `interfaces/`** |
| Collaboration | `collaboration/<npm-package>/{classes,enums,interfaces}/` + `Overview.md` |

`modules/` is the index layer. Each file there describes one namespace and links out to its classes, interfaces, enums and functions. Reading it first gives a cheap overview before opening individual type files.

The three component trees (`designer`, `excelio`, `collaboration`) are self-contained — each has its own `modules/` and does **not** appear in the root `modules/`. Two differences to expect:

- `collaboration/` adds a package level (10 packages: `js-collaboration`, `js-collaboration-ot`, `spread-sheets-collaboration`, …). Each package has its own `Overview.md`; `js-collaboration-presence/` contains *only* an `Overview.md`. Naming here drops the `GC.Spread.*` prefix — files are bare names like `interfaces/IChangeSet.md`.
- `designer/` filenames keep the full `GC.Spread.Sheets.Designer.*` prefix.

## File anatomy

Every file follows the same shape. This is what the markup means:

```markdown
# Class: Worksheet                    ← kind + short name. Kind ∈ Class | Interface |
                                        Enumeration | Namespace
[Spread](../modules/GC.Spread.md).[Sheets](../modules/GC.Spread.Sheets.md).Worksheet
                                       ← breadcrumb = parent chain. All links relative.
## Hierarchy                           ← classes only; ↳ marks subclasses
## Table of contents                   ← member index; jump to anchors
### <a id="getrange" name="getrange"></a> getRange
                                       ← anchor id is the LOWERCASED member name
▸ **getRange**(`row`, `col`, `rowCount?`, ...): [`CellRange`](GC.Spread.Sheets.CellRange.md)
#### Parameters
| Name | Type | Description |       ← `?` suffix on a name means the param is optional
#### Returns
```

Member markers:

| Marker | Meaning |
| --- | --- |
| `▸` | method (or function) |
| `•` | property, enum member, or variable |
| `• **new X**()` | constructor |
| `` • `Static` **X**: `string` `` | static member |
| `` • **x** = `1` `` | enum member and its numeric value |
| `___` | separator between members |
| `` **`example`** `` + ` ```javascript ` | runnable example — the most reliable usage source |
| `` **`param`** `` | describes an event-argument field |

Two things that trip up naive parsing:

- **Overloads share one heading.** A method with multiple signatures has several `▸ **name**(...)` blocks stacked under a single anchor. Read all of them before concluding a signature. `Worksheet.getRange` has two.
- **Events are plain string constants**, not typed emitters: `` • `Static` **CurrentUserChanged**: `string` ``. They live in `Events` classes (`GC.Spread.Sheets.Events`, `GC.Spread.Sheets.Designer.Events`, `GC.Spread.Common.Events`).

**Linking to a specific member:** `<file>.md#<lowercased-member-name>`, e.g. `classes/GC.Spread.Sheets.Worksheet.md#getrange`. Overloads share one anchor.

## Working with Chinese descriptions

Type names, signatures and code samples need no translation — read them directly. Only the prose is Chinese. The recurring phrases are formulaic enough to parse positionally:

| Chinese | Meaning |
| --- | --- |
| 表示… | "represents…" — the definition |
| 如果未提供此参数，则默认值为 X | default value if the argument is omitted |
| 获取… / 设置… | getter / setter |
| 此示例… | "this example…" — precedes sample code |

Treat the `Description` column and text after `#### Returns` as the authoritative behavioral notes; they often contain constraints the signatures do not express.

## toc.json

Each version ships `toc.json` (~924 KB) with 1263 entries — the original documentation site's navigation tree. Fields that matter: `Text` (fully-qualified name), `DisplayName`, `Type` (`Api` | `ApiAppend` | `file`), `DocumentPath`, `ParentId`.

For `Type: "Api"` entries, the file is at `<version>` + `DocumentPath` + `.md`.

**Use it for structure, not for exact lookup.** Neither `Text` nor `DisplayName` is a unique key (30 and 43 duplicates respectively), and `Type: "file"` entries are navigation groups with no corresponding file. `v18.0` has no `toc.json` at all. When you need a specific symbol, `grep` the Markdown — it is always correct, `toc.json` is not.

## Gotchas

- `excelio/` has no `interfaces/` directory. Its `classes/` holds exactly one file.
- `collaboration/` did not exist before v18.0.
- A `-1` suffix means a name collision, not a version or overload.
- Root `modules/` covers only the core library. Designer, ExcelIO and Collaboration APIs are **not** reachable from it — go to their own trees.
- Descriptions can be stale or thinner than the code. Cross-check non-trivial behavior against [the official docs](https://www.grapecity.com.cn/developer/spreadjs).
